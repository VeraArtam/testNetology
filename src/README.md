1. Перечень автоматизируемых сценариев:
1) Переход на страницу формы через "Каталог курсов" в верхней части страницы
2) Переход на страницу формы через окно "Освоить профессию"
3) Переход на страницу формы через окно "Программирование"
4) Переход на страницу формы через окно "Полный каталог"
5) Переход на страницу формы через ссылку внизу страницы "Программирование"
6) Заполнение и отправка формы с валидными данными
7) Заполнение и отправка формы с различными невалидными данными (не указано или неверное значение имени, проверка граничных значений, не указан номер телефона, неверный формат номера телефона, телефон уже зарегистрированного пользователя, неверный формат емейл, пустой емейл, емейл зарегистрированного пользователя, не выбрана кнопка принятия условий)

2. Перечень используемых инструментов с обоснованием выбора:
1) Java + Selenide. Java широко используется в автотестировании, Selenide упрощает написание тестов, автоматически управляет ожиданиями
2) JUnit 5. Современный стандарт для Java-проектов, гибкие аннотации, параметризация, интеграция с Maven/Gradle.
3) Page Object. Позволяет отделить локаторы и действия страницы от логики тестов, упрощает поддержку при изменении вёрстки.
4) Allure Report. Наглядные отчёты с шагами, скриншотами, вложениями; интеграция с JUnit и Selenide
5) Git + GitHub. Удобство совместной работы
6) Maven или Gradle. Упрощает подключение библиотек и запуск тестов
7) CI. Автоматический запуск тестов
8) Faker. Позволяет легко создавать случайные валидные/невалидные данные

3. Доступы и разрешения
1) Доступ к тестовой среде. Доступ к тестовому режиму либо писменное разрешение владельца
2) Разрешение на отправку тестовых заявок. 
3) Доступ к репозиторию для размещения тестового кода
4) Доступ к CI/CD
Данные:
5) Валидные тестовые данные: список имён на кириллице (включая граничные случаи: 2 буквы, двойное имя, с «ё»), список валидных номеров телефонов в разных форматах.
6) Невалидные тестовые данные: имена с латиницей (если запрещена), спецсимволы, цифры, пустые строки, слишком длинные строки, невалидные номера телефонов.
7) Актуальные локаторы элементов

4. Перечень и описание возможных рисков при автоматизации:
1) Изменение вёрстки / локаторов. Формы и кнопки могут менять классы или структуру.
2) Динамическая загрузка контента. Элементы могут появляться с задержкой.
3) Капча или антибот-защита
4) Отправка реальных заявок на production

   QA Lead / Manual QA
